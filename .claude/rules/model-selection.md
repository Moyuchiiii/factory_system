# モデル選択ルール

## モデル割り当て

| ロール | モデル | 変更可否 |
|---|---|---|
| リード（メインターミナル） | Opus | 固定・変更不可 |
| researcher | Sonnet | デフォルト |
| planner | Sonnet | デフォルト |
| critic | Opus | 固定（精度優先） |
| builder | Sonnet | デフォルト |

## Haiku に格下げしてよいケース

以下のすべてを満たす場合のみ:
- 判断・推論が一切不要
- パターンが決まった定型処理
- 具体例: データ整形、転記、件数カウント、フォーマット変換

## Sonnet を維持するケース（デフォルト）

以下のいずれかに該当する場合:
- Web 検索・情報収集
- 分析・比較・要約
- コード生成・修正
- ファイル生成・操作
- その他、少しでも判断が伴う作業

IMPORTANT: **迷ったら Sonnet**。Haiku は「判断ゼロ × 単純作業」のときだけ。

## critic だけ Opus にする理由

critic は設計の穴・技術的矛盾・収益モデルの問題を見つける役割。
planner（Sonnet）と同じモデルでは批判が甘くなるため、
より深い推論ができる Opus を割り当てる。
