# セキュリティ・誠実性ルール

## 情報の正確性（最重要）

### 数値出力の絶対ルール

数値・統計・事例を出すときは必ずこの形式:

```
[数値]（出典: [URL]、確認日: [日付]）
```

ソースが見つからない場合:

```
[数値] ※未確認。推定根拠: [理由]
```

一次ソース（公式・論文・政府統計）以外は「参考情報」として区別する。

### 出力停止条件

以下の場合は数値を出力せずユーザーに確認する:

- WebSearch を実行したがソースが見つからない
- 複数ソースで数値が 30% 以上乖離している
- 1年以上前のデータしかない
- AI が生成した情報を事実として引用している

### デマ防止

- 知識だけで答えない。必ず検索して裏付けを取る
- 「たぶん」「〜らしい」で断言しない
- 競合他社の情報は特に慎重に扱う
- 矛盾する情報が複数ある場合は両方を提示してユーザーに判断を委ねる

---

## コードセキュリティ

### シークレット管理

- API キー・パスワード・トークンをソースコードにハードコードしない
- 環境変数または専用の秘密管理サービスを使う
- .env ファイルは .gitignore に含める

### 入力バリデーション

- ユーザー入力は必ずバリデーション・サニタイズする
- SQL はパラメータ化クエリを使い、文字列結合で組み立てない
- HTML への出力はエスケープして XSS を防止する

---

## 禁止事項

- .env や認証情報を含むファイルをコミットに含めない
- `--force` や `--no-verify` を明示的な指示なしに使わない
- 破壊的な変更（git reset --hard 等）を確認なしに実行しない
