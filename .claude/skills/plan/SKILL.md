# /plan スキル

`research.md` と `selected-repos.md` を読んで Claude Code プロジェクトの完全な設計図を作成する。
planner と critic が最大4ラウンドで設計品質を徹底的に高める。

---

## フロー

### ステップ1: 前提確認

以下が存在することを確認する:
- `research.md` ✓
- `selected-repos.md` ✓

なければ該当スキルを先に実行するよう案内する。

### ステップ2: planner による設計

planner エージェントに以下を設計させる:

**CLAUDE.md の設計**
- プロジェクトの目的・概要
- 基本方針と重要ルール
- スキル一覧と使い方
- ファイル構成の説明

**`.claude/rules/` の設計**
- 必要なルールファイルとその内容
- soul.md（プロジェクト固有の存在意義）
- workflow.md（プロジェクト固有のフロー）

**`.claude/skills/` の設計**
- 必要なスキルの一覧
- 各スキルの入力・出力・フロー・エージェント呼び出し

**`.claude/agents/` の設計**
- 必要なエージェントの一覧
- 各エージェントのモデル・役割・制約

**実装計画**
- ファイル生成の順序
- リポジトリインストールの手順（selected-repos.md 参照）
- 想定失敗パターンと対策

### ステップ3: critic ループ（最大4ラウンド）

各ラウンドで critic が以下を確認:
- 技術的実現可能性（実装できない設計になっていないか）
- 収益モデルとの整合性（research.md の内容と矛盾していないか）
- スキル設計の完全性（入力・出力・フローが明確か）
- builder がそのまま実装できる粒度か
- 前ラウンドの修正が正しく反映されているか

APPROVE が出たら即終了。

### ステップ4: 状態保存

`.factory/state.json` を更新。

---
