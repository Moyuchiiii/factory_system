# /research スキル

ビジネスアイデアを決定し、収益化の設計図となる `research.md` を生成する。
全情報に裏取り・ソース記載必須。critic と最大3ラウンドで品質を担保する。

---

## フロー

### ステップ1: アイデアの受け取り

**ユーザー指定あり**
→ アイデアを受け取り、researcher エージェントに深掘り調査を依頼する

**ユーザー指定なし（自律リサーチ）**
1. `book/summaries/` と `book/factory-repos-selection.md` を読む
2. researcher エージェントに以下を並列で調査させる:
   - WebSearch: 「2026 AI副業 月収 事例」「フリーランス 収益化 Claude」等
   - WebSearch: 「indie hacker revenue 2026」「solo developer SaaS」等
   - 実現可能性スコアリング（技術難易度 / 市場規模 / 競合 / 初期コスト / 収益速度）
3. 上位3案をユーザーに提示してユーザーが選ぶ

### ステップ2: 詳細調査

選定されたアイデアについて researcher が以下を並列調査:
- 市場規模（WebSearch、出典付き）
- 競合3社以上（実在確認・URL付き）
- 収益モデルの実例（実際に稼いでいる事例・ソース付き）
- 技術要件（必要スタック・工数・難易度）
- リスクと対策

### ステップ3: critic ループ（最大3ラウンド）

```
Round 1: researcher が research.md を生成
Round 2: critic が批判（ソース信頼性・数値の根拠・競合分析の漏れ等）
Round 3: researcher が修正
Round 4: critic が再評価
Round 5: researcher が再修正
Round 6: critic が最終評価 → APPROVE or ESCALATE
```

APPROVE が出たら即終了（残ラウンドはスキップ）。

### ステップ4: 状態保存

`.factory/state.json` を更新:
```json
{ "currentStep": "research", "status": "completed" }
```

## 数値出力ルール（絶対厳守）

```
[数値]（出典: [URL]、確認日: [日付]）
```

ソースなし → 出力停止してユーザーに確認。

- 月収試算: [金額]（根拠: ...）

## 競合分析

| [実在する競合1] | ... | ... | ... |

## 技術要件

- 難易度: [1-5]
